# 10. 実装マイルストーン

小さく動くものを積み上げ、主役（リマインダー）に早く到達する順序にする。
各マイルストーンの終わりに「動くもの」と「テスト」がそろっている状態を目指す。

| # | マイルストーン | 内容 | 完了条件 |
|---|---|---|---|
| M0 | 土台づくり | 最低限の開発環境（[11_setup.md](11_setup.md)）：monorepo、Next.js と Express の骨組み | `pnpm dev` で web と api が起動する |
| M1 | ドメインロジック | `domain/`：更新日計算・金額換算・リマインダー計画 | ユニットテスト（03・09 の必須ケース）がすべて通る |
| M2 | DB | Docker（Postgres・Redis・Mailpit）、Prisma 導入、スキーマ、マイグレーション（CHECK・部分インデックス追記）、シード | `migrate dev` が通り、シードで画面確認用データが入る |
| M3 | 認証 | サインアップ、ログイン/ログアウト、セッション、Origin 検証、レート制限、メール認証・パスワードリセット（この時点ではメールは同期送信 or ログ出力でも可） | 認証 API の統合テスト |
| M4 | サブスク CRUD | API ＋ 画面（一覧・登録・詳細・編集・解約・再開・削除） | 認可テスト（他人のリソース 404）が通る |
| M5 | 可視化 | `/dashboard/summary` ＋ ダッシュボード画面（カード・棒・円・今後 30 日） | 数値が 03 の定義どおり |
| M6 | **非同期基盤** | BullMQ 導入、email キュー、MailSender（SMTP/Resend）、認証メールをキュー経由に変更、Bull Board | Mailpit で認証メールを受信できる |
| M7 | **リマインダー** | reminders 生成・再生成、reminder-scan、send-reminder、renewal-advance、配信停止 | 冪等性テスト（09 §2.1）がすべて通る |
| M8 | 設定・仕上げ | 設定画面、通知履歴、cleanup ジョブ、セキュリティヘッダー、空状態・エラー画面、ESLint/Prettier、CI | E2E ハッピーパスが通る |
| M9 | デプロイ | render.yaml、Resend ドメイン設定、本番環境変数、外部監視 | 本番で自分宛のリマインダーが届く |

## 動作確認のコツ（M7）

- 開発用に `notify_hour` を現在時刻に、オフセットを 0 に設定すると、その日の更新日のサブスクですぐ通知を試せる
- 開発環境限定の管理 API `POST /api/v1/dev/run-job/:name`（`NODE_ENV=development` のときだけルート登録）で定期ジョブを即時実行できるようにすると便利
- worker を 2 プロセス起動して重複送信が起きないことを Mailpit で目視確認する
