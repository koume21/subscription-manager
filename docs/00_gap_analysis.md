# 00. 構想メモの穴と決定事項

構想メモを実装可能なレベルまで詰めるにあたって見つかった「穴」（未定義・矛盾・考慮漏れ）と、
本設計での決定を一覧化する。各項目の詳細は参照先のドキュメントを参照。

## A. ドメイン（サブスクそのもの）の穴

| # | 穴 | なぜ問題か | 決定 | 参照 |
|---|---|---|---|---|
| A1 | 「更新日」をどう保持するか未定義 | 次回更新日だけを保存すると、過ぎた後に誰がいつ繰り上げるのかが決まらない | **起算日（アンカー日）＋請求サイクル** を正とし、`next_renewal_date` は派生値として保存（検索用）。定期ジョブで繰り上げる | 03, 07 |
| A2 | 月末問題（1/31 契約の翌月は？） | 単純に前回日付へ 1 か月足すと 1/31→2/28→3/28 と日付がずれていく | 毎回 **起算日から N サイクル後** を計算し、存在しない日は月末に丸める（1/31→2/28→3/31） | 03 |
| A3 | うるう日（2/29 起算の年額） | 平年に 2/29 が存在しない | 平年は 2/28 に丸める | 03 |
| A4 | 「月単位・年単位」以外の周期 | 3 か月ごと・半年ごとのサブスクが実在する | `interval_unit`（MONTH/YEAR）× `interval_count`（1〜12 / 1〜5）で表現。追加コストはほぼゼロ | 03, 04 |
| A5 | 無料トライアル | 「解約忘れ防止」の最重要ケースなのに考慮がない | `is_trial` フラグを持ち、初回請求日＝トライアル終了日として登録。メール文面を変える。初回更新後に自動で `false` | 03, 07 |
| A6 | 解約と削除の区別 | 「解約した」記録を残したいのか、誤登録を消したいのかが混ざっている | **解約**＝ステータスを `CANCELED` にする（履歴として残る・集計対象外・通知停止）、**削除**＝物理削除 | 03, 05 |
| A7 | 金額の型 | 浮動小数点だと誤差が出る | **整数（円）** で保持。多通貨は余力スコープなので円固定 | 03, 04 |
| A8 | 「月額合計」に年額サブスクを含めるか | 定義しないとグラフの数字が人によって変わる | 「月額換算合計」＝Σ(年額÷12 を含む) と「年額換算合計」を明示的に分けて表示。按分・推移・予測は余力スコープ | 03, 08 |
| A9 | 登録件数の上限 | 無制限だと悪用・性能劣化の余地 | 1 ユーザーあたり 200 件まで | 01 |

## B. リマインダー（主役）の穴

| # | 穴 | なぜ問題か | 決定 | 参照 |
|---|---|---|---|---|
| B1 | 「何日前」に通知するか未定義 | 要件として成立しない | ユーザー既定値（初期値 7 日前・1 日前）＋サブスク単位の上書き。0〜30 日、最大 3 個 | 07 |
| B2 | タイムゾーン・通知時刻 | 「1 日前」が UTC 基準だと深夜に届く／日付がずれる | ユーザーごとに `timezone`（既定 Asia/Tokyo）と `notify_hour`（既定 9 時）を持つ | 07 |
| B3 | 通知方式（遅延ジョブ vs 定期スキャン） | 遅延ジョブ方式だと、サブスク編集時に予約済みジョブの取消・再登録が必要になり不整合が起きやすい | **リマインダーを DB に実体化**（`reminders` テーブル）し、定期スキャンでキューに投入する「アウトボックス型」 | 07 |
| B4 | 重複送信 | ワーカー多重起動・リトライ・クラッシュで同じメールが複数回届く | 3 層で防ぐ：①DB ユニーク制約 ②キューの jobId 重複排除 ③メール API の Idempotency-Key | 07 |
| B5 | 送信失敗時の扱い | 一時障害で通知が消えると解約忘れが起きる | 指数バックオフで最大 5 回リトライ。最終失敗は `FAILED` として記録・ログ通知 | 07 |
| B6 | サーバー停止中に送信時刻を過ぎた通知 | 復旧後に古い通知が大量送信される／更新日後に「明日更新です」が届く | 更新日を過ぎた通知は送らず `SKIPPED(EXPIRED)`。更新日前なら遅れても送る | 07 |
| B7 | 登録直後で送信時刻が既に過去 | 例：3 日後更新のサブスクを登録、7 日前通知は過去 | 過去のオフセットは生成しない。ただし全オフセットが過去で更新日が未来なら、直近 1 通だけ即時送信 | 07 |
| B8 | 更新日を過ぎた後の扱い | 次回更新日が過去のまま残る | 毎時の繰り上げジョブで次サイクルへ進め、リマインダーを再生成 | 07 |
| B9 | 未認証メールアドレスへの送信 | 他人のアドレスにメールが届く（スパム踏み台） | メール認証済みユーザーにのみリマインダーを送る | 06, 07 |
| B10 | 配信停止手段 | 受信者がメールから止められないと不親切・迷惑メール判定されやすい | 署名付きトークンのワンクリック配信停止リンク（`List-Unsubscribe` ヘッダー対応） | 05, 07 |
| B11 | 同日に複数サブスクが更新 | 通知が何通も届く | v1 は **1 リマインダー = 1 通** とする（冪等性設計を単純に保つため）。まとめ送信は将来課題と明記 | 07 |
| B12 | 設定変更時の再計算 | タイムゾーンや既定オフセットを変えたのに古い予定で送られる | 変更時に該当ユーザーの未送信リマインダーを同一トランザクションで再生成 | 07 |

## C. 認証・セキュリティの穴

| # | 穴 | 決定 | 参照 |
|---|---|---|---|
| C1 | セッションか JWT か未定 | **サーバーサイドセッション（DB 保存）＋ HttpOnly Cookie**。即時失効が容易で、学習用としても安全 | 06 |
| C2 | Next.js と Express が別オリジンになり Cookie/CORS が複雑 | Next.js の rewrites で `/api/*` を Express へプロキシし **同一オリジン化** | 02, 06 |
| C3 | メールアドレス所有確認がない | サインアップ時にメール認証を必須化（未認証でもログインは可、通知は送らない） | 06 |
| C4 | パスワード忘れの考慮がない | パスワードリセット（1 時間有効・1 回限り・成功時に全セッション失効） | 06 |
| C5 | ブルートフォース対策 | IP 単位＋アカウント単位のレート制限（Redis） | 06 |
| C6 | アカウント列挙 | サインアップ・ログイン・リセットで「登録済みか」が分からない応答にする | 06 |
| C7 | 他人のデータへのアクセス（IDOR） | 全クエリに `user_id` 条件を必須化。存在しない／他人のリソースは区別せず 404 | 06 |
| C8 | CSRF | SameSite=Lax Cookie ＋ Origin ヘッダー検証 | 06 |
| C9 | 退会 | パスワード再入力で物理削除（関連データはカスケード削除） | 05, 06 |
| C10 | 管理画面（ジョブダッシュボード）の公開 | 本番では公開しない（Basic 認証＋環境変数で無効化可） | 09 |

## D. 非機能・運用の穴

| # | 穴 | 決定 | 参照 |
|---|---|---|---|
| D1 | API とワーカーの分離 | 同一コードベース・別エントリーポイント・別プロセス | 02 |
| D2 | Redis のメモリ退避設定 | BullMQ は `maxmemory-policy=noeviction` が必須。Render Key Value の設定を確認 | 09 |
| D3 | DB マイグレーションの実行タイミング | デプロイ前コマンドで `prisma migrate deploy` | 09 |
| D4 | 開発時のメール送信 | Mailpit（ローカル SMTP＋Web UI）で実送信しない | 09 |
| D5 | 日付・時刻の型 | 日付は `DATE`（ユーザーのローカル日付）、時刻は `timestamptz`（UTC） | 03, 04 |
| D6 | 同時編集 | 単一ユーザー利用のため **後勝ち** を許容（楽観ロックは導入しない）と明記 | 05 |
| D7 | テスト戦略 | 日付計算・冪等性を重点テスト。DB は実 Postgres でテスト | 09 |
| D8 | フロント/バックの型・バリデーションの二重管理 | monorepo の共有パッケージに zod スキーマを置き、両者で使う | 02 |

## E. 明示的にスコープ外としたもの

- 多通貨対応・為替レート自動取得（余力スコープ）
- 支出予測・カテゴリ別割合・推移分析（余力スコープ）。そのため **カテゴリ項目自体も v1 では持たない**
- メールアドレス変更、ソーシャルログイン、2 要素認証
- 同日更新分のまとめ送信（ダイジェスト）
- メールのバウンス（不達）検知 Webhook
- 価格改定の履歴管理（金額は上書き更新）
- 管理者ロール・複数人での共有
