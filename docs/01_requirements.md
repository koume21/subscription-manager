# 01. 要件定義

## 1. 目的

- 契約中のサブスクを一元管理し、支出を把握できるようにする
- 更新日前にメールで通知し、**解約忘れ・トライアル終了忘れ** を防ぐ
- （開発目的）非同期処理・ジョブキュー・定期実行・外部 API 連携・冪等性を実践的に学ぶ

## 2. 想定ユーザー

- 個人。自分のサブスクのみを管理する（共有・チーム機能なし）
- 日本在住を主に想定（既定タイムゾーン Asia/Tokyo、通貨は円）

## 3. 機能要件

### 3.1 アカウント

| ID | 要件 |
|---|---|
| F-AUTH-01 | メールアドレス＋パスワードでサインアップできる |
| F-AUTH-02 | サインアップ後、確認メールのリンクでメールアドレスを認証する（有効期限 24 時間、再送可） |
| F-AUTH-03 | ログイン／ログアウトできる |
| F-AUTH-04 | パスワードを忘れた場合、メールでリセットできる（有効期限 1 時間） |
| F-AUTH-05 | ログイン中にパスワードを変更できる（現在のパスワード必須、他セッションは失効） |
| F-AUTH-06 | 退会できる（パスワード再入力、全データ削除） |

### 3.2 サブスク管理（CRUD）

| ID | 要件 |
|---|---|
| F-SUB-01 | サブスクを登録できる（項目は下表） |
| F-SUB-02 | 一覧表示できる（ステータスで絞り込み、次回更新日・金額・名前で並び替え） |
| F-SUB-03 | 詳細を表示できる（通知履歴を含む） |
| F-SUB-04 | 編集できる |
| F-SUB-05 | 「解約済み」にできる（通知停止・集計対象外・一覧に履歴として残る） |
| F-SUB-06 | 解約済みを「契約中」に戻せる（次回更新日を再計算） |
| F-SUB-07 | 削除できる（物理削除。誤登録の取り消し用途） |
| F-SUB-08 | 1 ユーザーあたり最大 200 件 |

**登録項目**

| 項目 | 必須 | 制約 |
|---|---|---|
| サービス名 | ○ | 1〜100 文字 |
| 金額（円） | ○ | 0〜10,000,000 の整数 |
| 請求サイクル単位 | ○ | 月 / 年 |
| 請求サイクル間隔 | ○ | 月：1〜12、年：1〜5（既定 1） |
| 初回請求日（起算日） | ○ | 日付。過去日も可（既存契約の登録用） |
| 無料トライアル中 | − | 真偽値。真の場合、初回請求日＝トライアル終了日の意味になる |
| 通知する | − | 真偽値（既定 true） |
| 通知タイミング | − | 未指定ならユーザー既定値を使う。0〜30 日前、最大 3 個 |
| 解約ページ URL | − | http/https の URL、2048 文字以内。通知メールに記載 |
| メモ | − | 1000 文字以内 |

### 3.3 支出の可視化

| ID | 要件 |
|---|---|
| F-VIS-01 | 契約中サブスクの **月額換算合計** と **年額換算合計** を表示する |
| F-VIS-02 | 契約中の件数を表示する |
| F-VIS-03 | サービス別の月額換算額を棒グラフで表示する（降順） |
| F-VIS-04 | 請求サイクル別（月払い／年払い）の内訳を円グラフで表示する |
| F-VIS-05 | 今後 30 日以内に更新されるサブスクを一覧表示する |

> 「実質月額の算出（按分）」「カテゴリ別割合」「推移」は余力スコープのため含めない。
> F-VIS-01 の月額換算は「年額 ÷ 12」の単純換算であり、按分計算ではない（[03](03_domain_logic.md) 参照）。

### 3.4 更新リマインダー（主役）

| ID | 要件 |
|---|---|
| F-REM-01 | 次回更新日の N 日前（ユーザーのタイムゾーンで通知時刻）にメールを送る |
| F-REM-02 | ユーザー既定の通知タイミング（初期値：7 日前・1 日前）と通知時刻（初期値 9 時）を設定できる |
| F-REM-03 | サブスク単位で通知タイミングの上書き・通知 OFF ができる |
| F-REM-04 | アカウント全体で通知を OFF にできる |
| F-REM-05 | 同じ通知は **二度送らない**（冪等性） |
| F-REM-06 | 一時的な送信失敗は自動リトライする |
| F-REM-07 | 更新日を過ぎたサブスクは自動で次回更新日へ繰り上がる |
| F-REM-08 | メール内のリンクからワンクリックで通知を停止できる |
| F-REM-09 | 通知履歴（送信済み・スキップ・失敗）をサブスク詳細で確認できる |
| F-REM-10 | トライアル中のサブスクは「トライアル終了・初回課金」である旨を強調した文面で送る |
| F-REM-11 | メール認証が済んでいないユーザーには送らない |

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | API の p95 応答 300ms 以内（一覧 200 件時） |
| 通知精度 | 予定時刻から **15 分以内** に送信キューへ投入される |
| 信頼性 | ワーカー再起動・多重起動でも通知の欠落・重複が起きない（メール API の冪等性保持期間内） |
| 可用性 | 練習用のため SLA は設けない。ただし停止からの復旧時に通知を正しく追いつく（B6 参照） |
| セキュリティ | OWASP Top 10 の主要項目に対策（[06](06_auth_security.md)） |
| 保守性 | TypeScript strict、Lint/Format、主要ロジックのユニットテスト、CI で自動実行 |
| 観測性 | 構造化ログ（JSON）、リクエスト ID、ジョブ ID をログに含める |
| 対応ブラウザ | 最新版 Chrome / Safari / Firefox / Edge、スマホ幅（375px〜）でも崩れない |
| 国際化 | UI は日本語のみ |
